Generar eventos de telemetría E2E al sink n8n

Un lab de identidad se ve pobre con el historial vacío. Para que los dashboards y los

workflows de respuesta tengan de qué alimentarse, montamos un **generador de eventos

E2E** que no inventa datos: autentica contra el tenant real de IBM Verify, extrae

usuarios y grupos reales vía SCIM y dispara eventos de telemetría (login, MFA,

SCIM, sesión, riesgo, governance) a un webhook de n8n que los persiste.

Eventos llegando en vivo

*Las ejecuciones entran en tiempo real a medida que el generador dispara POSTs al webhook (modo webhook, auto-refresh). Cada tarjeta Succeeded = un evento persistido.*

Cómo se generan (terminal)

Un único comando: secret_run inyecta el client_id/client_secret como variables de

entorno (el valor nunca aparece en el transcript) y corre el generador. Bajo el capó

hace el token OAuth2, el pull SCIM de identidades reales y los 100 POST al webhook.

Reproducir el lab (paso a paso)

Prerrequisitos: Node 18+, un tenant IBM Verify y una instancia n8n con un webhook.

  1. API client en Verify — *Security › API access* → crear un API client con

entitlements Manage all users + Manage all groups. Copiar client_id y

client_secret (el secret se muestra 1 sola vez).

  1. Webhook en n8n — workflow con nodo *Webhook* (POST, path isv-events) → *Set*

(captura headers/body) → *Data table* (o el sink que prefieras). Activarlo.

  1. Guardar los secretos (fuera del código). Con el gestor local:

```

secret_set api-client-id

secret_set api-client-secret

```

  1. Correr el generador (100 eventos; el secret se inyecta como env):

```

cd pike-web/janus

export PATH="/c/Program Files/nodejs:$PATH"

secret_run inject {CID:api-client-id, CSEC:api-client-secret} node isv-event-gen.mjs 100

```

Salida esperada: real tenant: 140 users, 20 groups → DONE sent=100 fail=0.

  1. Verificar — en n8n, /workflow/<workflow-id>/executions: todas en modo webhook,

estado Succeeded. O por API: GET /executions?workflowId=<id>.

El script completo (isv-event-gen.mjs)

Copiá este archivo a pike-web/janus/. Autocontenido, sin dependencias (usa fetch nativo).

// E2E ISV event generator: pulls REAL users+groups from the IBM Verify tenant
// (OAuth2 client_credentials) and emits lifecycle/SSO events referencing those
// real identities to the n8n webhook.
const T = "https://tenant.verify.ibm.com";
const WEBHOOK = "https://n8n.example.com/webhook/isv-events";
const N = Number(process.argv[2] || 100);
const id = process.env.CID, sec = process.env.CSEC;

// 1) token OAuth2 (client_credentials)
const tr = await fetch(`${T}/v1.0/endpoint/default/token`, {
  method: "POST", headers: { "content-type": "application/x-www-form-urlencoded" },
  body: new URLSearchParams({ grant_type: "client_credentials", client_id: id, client_secret: sec })
});
const { access_token: A } = await tr.json();
if (!A) { console.log("no token"); process.exit(1); }
const H = a => ({ authorization: "Bearer " + A, accept: a || "application/json" });

// 2) identidades REALES del tenant (SCIM 2.0)
const ur = await fetch(`${T}/v2.0/Users?count=200&attributes=userName,emails,name,displayName`, { headers: H("application/scim+json") });
const users = (await ur.json()).Resources || [];
const gr = await fetch(`${T}/v2.0/Groups?count=50&attributes=displayName`, { headers: H("application/scim+json") });
const groups = ((await gr.json()).Resources || []).map(g => g.displayName);
console.log(`real tenant: ${users.length} users, ${groups.length} groups`);

const APPS = ["WordPress (OIDC)", "n8n", "Salesforce (SAML)", "Slack", "GitHub Enterprise", "Jira"];
const EVENTS = [
  ["authentication", "sso.login.success"], ["authentication", "sso.login.success"],
  ["authentication", "sso.login.failed"], ["mfa", "mfa.challenge.issued"],
  ["mfa", "mfa.verify.success"], ["mfa", "fido2.authenticate"],
  ["provisioning", "scim.user.updated"], ["provisioning", "scim.group.member.added"],
  ["session", "session.created"], ["session", "session.revoked"],
  ["password", "password.changed"], ["risk", "risk.score.evaluated"],
  ["governance", "access.cert.reviewed"], ["authentication", "sso.logout"]
];
const rnd = a => a[Math.floor(Math.random() * a.length)];
const ip = () => `${rnd([190,201,181,200])}.${(Math.random()*255)|0}.${(Math.random()*255)|0}.${(Math.random()*255)|0}`;
const geos = ["San Jose, CR", "Miami, US", "Madrid, ES", "Bogota, CO", "Sao Paulo, BR"];

// 3) por cada iteracion: identidad real + evento sintetizado -> POST al webhook
let ok = 0, fail = 0;
for (let i = 0; i < N; i++) {
  const u = rnd(users);
  const email = (u.emails && u.emails[0] && u.emails[0].value) || `${u.userName}@acme.example.com`;
  const [cat, type] = rnd(EVENTS);
  const risk = rnd(["low", "low", "low", "medium", "high"]);
  const ev = {
    source: "ibm-verify", tenant: "tenant.verify.ibm.com",
    event_category: cat, event_type: type,
    subject: { id: u.id, userName: u.userName, displayName: u.displayName || u.userName, email },
    group: rnd(groups), application: rnd(APPS),
    result: type.includes("failed") ? "failure" : "success",
    mfa_method: rnd(["fido2", "totp", "verify-push", "email-otp", "none"]),
    risk_level: risk,
    risk_score: risk === "high" ? 70 + ((Math.random()*30)|0) : risk === "medium" ? 40 + ((Math.random()*25)|0) : (Math.random()*30)|0,
    ip: ip(), geo: rnd(geos), user_agent: "Mozilla/5.0 (demo lab)",
    seq: i, occurred_at: new Date(Date.now() - ((Math.random()*7*864e5)|0)).toISOString()
  };
  try {
    const r = await fetch(WEBHOOK, { method: "POST", headers: { "content-type": "application/json", "x-isv-source": "tenant-e2e" }, body: JSON.stringify(ev) });
    r.ok ? ok++ : (fail++, fail <= 3 && console.log("HTTP", r.status, await r.text()));
  } catch (e) { fail++; fail <= 3 && console.log("ERR", e.message); }
}
console.log(`DONE sent=${ok} fail=${fail} (events built from REAL tenant identities)`);

  • El workflow en el editor — Webhook ISV → Capture payload → Save to isv_events:

  • Un evento tal como queda capturado por el nodo *Capture payload* (identidad real

  • Conteo acumulado: 633 ejecuciones, 100% success, todas en modo webhook

(verificado vía API de n8n). Cada corrida de node isv-event-gen.mjs 100 añade 100.

Para humanos

Por qué "E2E real": el que las identidades salgan del tenant vivo (no de una lista

hardcodeada) hace que los labs sean creíbles — los mismos usuarios que ves en Verify

aparecen en el historial de eventos. El único trozo sintético es el tipo de evento,

porque el API client de este tenant no tiene scope sobre el Activity/Events API

(GET /v1.0/events → 403); con ese scope, el generador replicaría eventos históricos

reales en vez de simularlos.
